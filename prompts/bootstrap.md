# Bootstrap Synthesis

Build an initial evidence-backed map of projects, technical scope, capabilities, experience, voice, preferences, and working style. Produce project dossiers only from project-specific evidence and distinguish first-party work, forks, third-party code, collections, experiments, archives, and duplicates. Dependencies describe project technology but never prove personal skill. Preserve safe user-authored excerpts as voice samples, and emit `voice_style` observations only for explicit preferences or stable language patterns supported across at least three sessions, two dates, and two projects. Separate deliberate voice from typos, assistant wording, and project-specific vocabulary. Preserve every contradiction, ambiguity, and missing timeline fact in `review_items` with a narrow question. Do not invent biography details.

Keep the first map selective: prefer durable identity, consequential project decisions, attributable capabilities, reusable lessons, and genuinely stable patterns. Routine inventories, transient implementation state, exact counts, single-task instructions, and exhaustive technical recaps are evidence context, not standalone knowledge. When an aggregate `feedback_profile` is available in a reusable installation, use it only as ranking guidance; a fresh installation may have none.
